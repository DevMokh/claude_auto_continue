# المرحلة الأولى: تقرير إمكانيات التكامل والحدود

> هذا التقرير مبني على معرفة بنظام Android وليس على اختبار فعلي لتطبيق Claude على جهاز. كل بند "غير مثبت" يحتاج Dump حقيقي للواجهة من هاتفك قبل الاعتماد عليه.

## بيئة التنفيذ الحالية

| الأداة | الحالة |
|---|---|
| Flutter / Dart | غير متوفر |
| Android SDK / Gradle | غير متوفر |
| اتصال إنترنت (لتنزيل SDK والتبعيات) | غير متاح |
| جهاز Android حقيقي | غير متاح |

**النتيجة:** هنا يمكن كتابة الكود وملفات المشروع وضغطها، لكن لا يمكن تشغيل `flutter pub get` أو `flutter analyze` أو `flutter test` أو بناء APK. أي كود يُسلَّم من هنا يُعتبر **غير مُجمَّع وغير مُختبر** حتى تبنيه على جهازك أو عبر CI.

## جدول الإمكانيات

| الوظيفة | إمكانية التنفيذ | القيود | طريقة الاختبار |
|---|---|---|---|
| فتح تطبيق Claude | ممكن (`getLaunchIntentForPackage("com.anthropic.claude")` مع `<queries>` في Manifest) | لا يوجد Deep Link موثوق لمحادثة محددة؛ المستخدم يفتحها يدويًا | تشغيل على الهاتف |
| قراءة واجهة Claude | مشروط | يعتمد على كون العناصر مكشوفة لـ Accessibility (labels / text). لم يُتحقق منه | Dump لشجرة `AccessibilityNodeInfo` على الهاتف |
| اكتشاف انتهاء الرد / استمرار الكتابة | غير مضمون | لا إشارة رسمية؛ يُستنتج من تغيّر النص أو ظهور زر Stop | مراقبة عملية |
| اكتشاف Usage Limit | مشروط | مطابقة نص؛ تتغير الصياغة واللغة والإصدار | رسالة حد حقيقية |
| اكتشاف عودة الاستخدام | غير مضمون | اختفاء الرسالة وحده ليس دليلًا؛ المؤشر الأقوى هو أن حقل الإدخال وزر الإرسال أصبحا مفعّلين | اختبار طويل |
| الضغط على Continue | مشروط | يجب أن يظهر الزر كعنصر قابل للنقر بنص مطابق | اختبار عملي |
| كتابة "كمل" وإرسالها | مشروط | `ACTION_SET_TEXT` ثم النقر على زر الإرسال؛ قد يفشل إن كان الحقل مخصصًا غير قياسي | اختبار محادثة |
| العمل والشاشة مغلقة | **غير ممكن عمليًا** | Accessibility لا تتفاعل مع شاشة مقفلة أو مطفأة | اختبار ليلي |
| الخدمة الأمامية | ممكن | Android 14 يتطلب `foregroundServiceType` مصرّحًا (مثل `specialUse`) | Android 14 حقيقي |
| الاستمرار بعد إعادة التشغيل | جزئي | خدمة Accessibility تُستعاد من النظام إن بقي تفعيلها، لكن المستخدم يجب أن يفتح Claude والمحادثة بنفسه | إعادة تشغيل فعلية |

## القيود الحرجة لسيناريو "التشغيل قبل النوم"

1. **الشاشة يجب أن تبقى مضاءة وغير مقفلة وClaude في المقدمة.** الحل الواقعي: توصيل الشاحن مع خيار المطور "Stay awake" وعدم وجود قفل شاشة. غير ذلك لن تعمل الأتمتة.
2. **تفعيل Accessibility يدوي فقط.** لا يمكن تفعيله برمجيًا. وعلى Android 13+ للتطبيقات المثبّتة خارج المتجر يلزم السماح من "Restricted settings" أولًا.
3. **تحسين البطارية** قد يقتل الخدمة المساندة؛ يلزم استثناء التطبيق، لكن الشركات المصنعة (Xiaomi، Samsung، Huawei) تضيف قيودًا إضافية لا يمكن ضمانها.
4. **تحديثات تطبيق Claude** قد تكسر التعرف على العناصر دون سابق إنذار؛ لذلك التصميم الصحيح هو الإيقاف والإشعار عند أي عنصر غير معروف.
5. **عدم التأكد = لا إجراء.** وهذا ما يطلبه تصميمك، وهو ما سيُنفَّذ.

## ملاحظة على شروط الاستخدام

أتذكر أن شروط Anthropic للمستهلك تمنع الوصول للخدمة بوسائل آلية عدا واجهة API ونحوها، وأتمتة تطبيق Claude عبر Accessibility قد تقع تحت ذلك. لم أتحقق من النص الحالي هنا، فراجعه بنفسك قبل الاعتماد على التطبيق. التطبيق مصمم أصلًا ألا يتجاوز الحدود أو يكرر الطلبات أثناء الحظر.

## ما يلزم لإكمال المشروع فعليًا

- بناء المشروع على جهازك (Flutter 3.x + Android SDK) أو عبر GitHub Actions.
- Dump لواجهة Claude (رسالة حد الاستخدام، حقل الإدخال، زر الإرسال، زر Continue) لضبط المحددات على الإصدار الحقيقي.
- جهاز Android 14 حقيقي للاختبار الواقعي.
