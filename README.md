# Claude Auto Continue

تطبيق Android (Flutter + Kotlin) لوظيفة واحدة: مراقبة تطبيق **Claude الرسمي** على الهاتف، والانتظار عند وصوله لحد الاستخدام، ثم إرسال كلمة **«كمل»** مرة واحدة عندما يتأكد أن Claude أصبح قادرًا على استقبال الرسائل. لا يتجاوز حدود Claude ولا يرسل طلبات أثناء الحظر.

> ## حالة المشروع: مكتوب بالكامل، غير مبني وغير مختبر
> كُتب هذا المشروع في بيئة بلا Flutter ولا Android SDK ولا إنترنت ولا هاتف. لذلك:
> - لم يُنفَّذ `flutter analyze` ولا `flutter test` ولا بناء APK.
> - **لا يوجد APK في هذه الحزمة.** تبنيه بخطوة واحدة (انظر أدناه).
> - كل أنماط التعرف على واجهة Claude (`ui_patterns.dart`) **تخمينات** حتى تعايرها على هاتفك.
> التفاصيل الصادقة في `TEST_REPORT.md` و`docs/PHASE1_REPORT.md`.

## البناء (تلقائي)

مجلد `android/` **موجود داخل المشروع** (Gradle 8.14 + AGP 8.11.1 + Kotlin 2.2.20، وهي الحزمة التي نجح بها مطوّرون مع Flutter 3.47.x؛ AGP 9 وKotlin 2.4 أحدث مما يدعمه 3.47 رسميًا). لذلك يكفي أي أمر عادي: `flutter pub get` ثم `flutter build apk`، بما في ذلك زر البناء في محرر الأكواد.

**على GitHub:** `.github/workflows/build.yml` يشتغل مع كل Push، يحلّل ويختبر ويبني الـ APK وينزّله في **Releases**، والسجلات في Artifacts وملخص الـ job. التحليل والاختبارات **لا توقف** بناء الـ APK؛ فشل البناء نفسه فقط يُفشل الـ job، وفي `dist/ERRORS.txt` أهم السطور.

**على جهازك:**
```bash
# يلزم: Flutter stable + JDK 17 + Android SDK
./scripts/bootstrap.sh            # Debug APK
./scripts/bootstrap.sh --release  # + Release APK
```
الناتج في `dist/`. لا يوجد `gradlew` ولا `gradle-wrapper.jar` في المجلد عمدًا: Flutter يحقنهما تلقائيًا عند أول بناء.

**التوقيع:** الـ Release يُوقَّع بمفتاح الـ debug (مقبول للتثبيت الشخصي، وليس للنشر).

**غير مُتحقَّق منه:** لم أبنِ المشروع فعليًا. إن اشتكى Flutter من إصدار AGP/Gradle/Kotlin فأرسل الرسالة وأعدّل الأرقام في `android/settings.gradle.kts` و`android/gradle/wrapper/gradle-wrapper.properties`.

## الاستخدام
1. ثبّت الـ APK، وافتح التطبيق، واتبع قائمة الإعداد في الشاشة الرئيسية: خدمة Accessibility، الإشعارات، استثناء البطارية.
   (Android 13+: لتطبيق مثبّت خارج المتجر، اسمح أولًا بـ "الإعدادات المقيّدة" من معلومات التطبيق.)
2. **عايِر الأنماط** من الإعدادات > "التقاط شجرة الشاشة": اضغط الزر، انتقل إلى Claude خلال 8 ثوانٍ، ارجع، وانسخ النتيجة. قارنها بـ `lib/core/constants/ui_patterns.dart` (انظر `docs/DEVICE_TEST_PLAN.md`).
3. افتح Claude على المحادثة المطلوبة، ثم ارجع واضغط **ابدأ**، ثم افتح Claude مجددًا على المحادثة.
4. للتشغيل الليلي: وصّل الشاحن، فعّل "إبقاء الشاشة مضاءة"، ولا تستخدم قفل شاشة آمنًا (قيد Android: لا تعمل الأتمتة على شاشة مقفلة).
5. إيقاف فوري: زر **إيقاف** في التطبيق أو في الإشعار الدائم.

## كيف يعمل (سلوك المحرك)
- يفحص الشاشة كل N ثوانٍ (افتراضي 5) عبر خدمة Accessibility محصورة بحزمة `com.anthropic.claude`.
- **Claude يكتب** → لا يفعل شيئًا. **انتهى الرد** → يعود للمراقبة **دون إرسال** (حتى لا يدخل في حلقة استهلاك).
- **حد الاستخدام** (يُرى فحصين متتاليين) → يسجّل وقت البداية ويدخل الانتظار. لا يخمّن موعد التجدد.
- **التجدد** = حقل الرسالة موجود ومفعّل وبلا رسالة حد وبلا إيقاف لـ 3 فحوص متتالية، ثم **تحقق مستقل أخير**. اختفاء الرسالة وحده لا يكفي.
- **الإرسال**: يُعلَّم "أُرسل" قبل لمس الواجهة (يمنع التكرار حتى لو انهار التطبيق)، يكتب «كمل» فقط إن كان الحقل فارغًا، يتحقق أن النص ظهر، ثم يضغط إرسال. إرسال واحد لكل فترة انتظار.
- بعد الإرسال: ينتظر ظهور كتابة Claude (45 ث). إن لم يتأكد → "يحتاج تدخلك" ويتوقف **دون إعادة إرسال**.
- **زر Continue** (إن ظهر بنص مطابق تمامًا): يُضغط مرة واحدة مع فترة تهدئة 30 ث.
- **يتوقف فورًا** عند: شاشة تسجيل دخول/تحقق أمني، حقل كلمة مرور، إيقاف Accessibility، فشل إرسال، بلوغ الحد الأقصى للمحاولات. ويتوقف أو يُنبّه (حسب الإعداد) عند شاشة غير معروفة لفترة طويلة.
- لا يرسل شيئًا أثناء انقطاع الإنترنت أو ظهور خطأ اتصال.

## قرارات تصميم يجب أن تعرفها
| القرار | السبب |
|---|---|
| لا إرسال "كمل" عند انتهاء رد عادي | وإلا حلقة لا نهائية تستهلك حصتك. الإرسال فقط بعد حد استخدام أو زر Continue |
| بدون WorkManager | لا يضيف شيئًا هنا: Android 12+ يمنع إعادة تشغيل خدمة أمامية من الخلفية، وخدمة Accessibility يعيدها النظام بنفسه |
| إعادة التشغيل تُرسل إشعار تذكير فقط | بعد الإقلاع لا بد أن تفتح Claude على المحادثة الصحيحة بنفسك؛ لن نشغّل الأتمتة على شاشة لا نعرفها |
| لا نفتح Claude تلقائيًا | قد يُفتح على محادثة أخرى فيُرسَل «كمل» في المكان الخطأ. التطبيق ينبّهك ولا يخمّن |
| "تفعيل المراقبة" في طلبك → "استئناف المراقبة بعد إعادة التشغيل" | مفتاح تفعيل عام لا معنى له مع زر Start |
| محرك Flutter يبقى حيًا بعد إغلاق الواجهة | `MainActivity` تحفظ المحرك في الكاش + خدمة أمامية. إن قتل النظام العملية، تفتح التطبيق فيستعيد الحالة |

## الصلاحيات
`ACCESS_NETWORK_STATE`, `POST_NOTIFICATIONS`, `FOREGROUND_SERVICE(+SPECIAL_USE)`, `WAKE_LOCK`, `RECEIVE_BOOT_COMPLETED`, وخدمة Accessibility (اختيارية، بموافقتك، محصورة بحزمة Claude، لا تقرأ كلمات المرور).
**لا يوجد `INTERNET`** في أي نسخة (لا release ولا debug). السجل في SQLite محلي ولا يُرسل لأي مكان.

## قيود معروفة
- الشاشة يجب أن تبقى مضاءة وغير مقفلة وClaude في المقدمة. هذا قيد Android لا حل برمجي له.
- قد تضع شركات (Xiaomi، Samsung، Huawei…) قيودًا إضافية على الخدمات الخلفية.
- قد يكسر تحديث Claude التعرف على العناصر؛ لذلك يتوقف عند أي شيء غير معروف.
- اكتشاف حد الاستخدام بمطابقة نص قصير (≤200 حرف)؛ نص محادثة قصير يحتوي العبارة نفسها قد يسبب إنذارًا كاذبًا (إرسال «كمل» واحد غير لازم كأسوأ حالة).
- عند وجود أكثر من حقل إدخال ظاهر، أو أكثر من زر مطابق، تُرفض العملية بدل التخمين.

## تنبيه الشروط
أتذكر أن شروط Anthropic للمستهلك تمنع الوصول الآلي للخدمة عدا API ونحوه، وأتمتة التطبيق عبر Accessibility قد تدخل تحت ذلك. لم أتحقق من النص الحالي؛ راجعه بنفسك قبل الاستخدام. الاستخدام على مسؤوليتك.
